# 纸浆作坊 · 原料验收入库与结算系统

零第三方依赖（Python 3.9+ 标准库 + SQLite/WAL），本地直接运行。覆盖：

来车验收入库（毛重/皮重/含水/杂质/等级）→ 净重 → 按档扣量 → 按合同分段价计价
→ 超限额双人复核 → 预付款 FIFO 抵扣付款 → 付款红冲（只能冲正不能改写）。
网页端与接口端双侧校验；已用真实 HTTP 服务验证全链路、并发付款与重启恢复。

## 业务规则

1. **净重** = 毛重 − 皮重（皮重 ≥ 毛重直接拒录，重量 Decimal 精确到 0.001kg）。
2. **按档扣量**：含水、杂质各自命中一档，扣点相加：
   `扣量 = 净重 ×（含水档% + 杂质档%）`，`结算重量 = 净重 − 扣量`。
   区间为左开右闭（边界值就低档，如含水 12.00% 不扣）。
3. **分段合同价**：同一供应商、同一等级可登记多个生效日期的价格段；
   计价只取**过磅日当天（含）之前已生效的最新一段**。未来价格即使存在也绝不使用
   （无已生效合同时计价报 422）。金额以**整数分**存储，杜绝浮点误差。
4. **双人复核**：结算金额 > 50,000.00 元时为待复核，须两名**不同**人员
   （且不能是制单人本人）依次复核后才可付款；未超限自动免复核。
5. **付款抵扣**：仅财务/主管可执行；预付款严格按 `received_at` 到账先后 FIFO
   抵扣。付款在单事务（`BEGIN IMMEDIATE`）内完成：
   **余额不足整单失败**——不写付款单、不写任何抵扣行、预付款分文不动。
   并发付款靠 SQLite 写锁串行化，同一张单不可能被付两次。
6. **冲正**：已付款单据只能红冲（必填原因），原付款/结算记录保留并标记
   `reversed`，预付款按原抵扣明细逐笔恢复；冲正后不能再付款。全程写审计日志。

## 主要接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` `/api/logout` | 会话（HttpOnly Cookie） |
| GET/POST | `/api/suppliers` | 供应商 |
| GET/POST | `/api/contracts` | 合同分段价（未来日期可录但不生效） |
| GET | `/api/tiers` | 含水/杂质扣量档 |
| GET/POST | `/api/prepayments` | 预付款到账登记（财务/主管） |
| GET/POST | `/api/receipts` | 验收入库（后端重算净重/扣量） |
| POST | `/api/receipts/{id}/settle` | 按生效合同段计价 |
| POST | `/api/settlements/{id}/review` | 复核（两名不同人员） |
| POST | `/api/settlements/{id}/pay` | FIFO 抵扣付款（整单事务） |
| POST | `/api/settlements/{id}/reverse` | 红冲（仅已付款，需原因） |
| GET | `/api/settlements` `/api/summary` | 单据列表 / 总览指标 |

网页在提交前做同构校验（数值格式、区间、皮重<毛重、日期不晚于今天等），
并提供「仅试算」实时预览净重、扣量与适用合同价；**一切以后端校验为准**。
